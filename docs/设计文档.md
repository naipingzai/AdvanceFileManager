# Material Files — 设计文档

> 版本: 1.1.0 | 最后更新: 2026-04-12

## 1. 项目概述

**Material Files** 是一款基于 Material Design 3 的 Android 文件管理器，支持 Android 5.0 (API 21) 及以上版本。项目采用 GPLv3 许可证。

### 1.1 设计目标

| 目标 | 描述 |
|------|------|
| **Material 3 设计语言** | 全面采用 Google Material Design 3 组件和规范，支持动态颜色 |
| **全面的文件管理** | 文件浏览、搜索、复制/移动/删除、压缩解压、权限管理 |
| **内置富媒体查看** | 图片/视频/音频/PDF/文本/十六进制/电子书查看器 |
| **实用工具集** | 文件搜索、重复文件/空文件夹查找、存储分析、应用管理、文件加密、媒体工具 |
| **Linux 文件系统友好** | 正确处理符号链接、硬链接、SELinux 上下文、POSIX 权限 |
| **Root 和 Shizuku 支持** | 通过 Root 或 Shizuku 实现跨进程系统级文件操作 |
| **完全离线** | 显式移除 INTERNET 权限，所有功能本地运行 |

### 1.2 核心设计原则

1. **Java NIO2 File API 架构**：所有文件操作统一通过 `java.nio.file` API 抽象层（AndroidRetroFile 回移）完成，不同文件源通过 `FileSystemProvider` 插件化接入
2. **ViewModel + LiveData 响应式**：UI 层通过 ViewModel 暴露的 LiveData 观察数据变化，分离数据获取和展示
3. **单 Activity + Multi-Fragment**：核心浏览使用 `FileListActivity`，工具模块使用 `ToolHostActivity` 作为宿主
4. **原生 JNI 性能层**：文件系统调用、压缩操作、音视频处理通过 C 层实现，避免 Java 层的性能瓶颈

## 2. 系统架构设计

### 2.1 分层架构

```
┌─────────────────────────────────────────────────────┐
│                    UI 层 (Material 3)                │
│  FileListActivity / ToolHostActivity / Viewers       │
│  Fragment + ViewModel + LiveData                     │
├─────────────────────────────────────────────────────┤
│                   业务逻辑层                          │
│  FileJob (文件操作) / Tools (工具模块) / Viewer (查看器)│
├─────────────────────────────────────────────────────┤
│              文件系统抽象层 (NIO2 File API)            │
│  FileSystemProvider: Linux / Archive / Content / SAF │
│  Root / Remote (IPC)                                 │
├─────────────────────────────────────────────────────┤
│                  原生层 (JNI / C)                     │
│  syscall.c / archive-jni.c / selinux-jni.c          │
│  ffmpeg-jni.c / hiddenapi.c                         │
├─────────────────────────────────────────────────────┤
│                 系统/硬件层                           │
│  Linux Kernel / MediaCodec / NDK                     │
└─────────────────────────────────────────────────────┘
```

### 2.2 文件系统 Provider 设计

采用 Java NIO2 的 `FileSystemProvider` SPI（Service Provider Interface）模式：

```
FileSystemProviders (单例入口)
├── LinuxFileSystemProvider      默认：直接通过 syscall 操作本地文件
├── ArchiveFileSystemProvider    压缩包：通过 libarchive 读写 ZIP/TAR/7Z/RAR 等
├── ContentFileSystemProvider    内容：通过 ContentResolver 访问 content:// URI
├── DocumentFileSystemProvider   SAF：通过 Storage Access Framework
└── RootFileSystemProvider       Root：通过 Shizuku/su 远程 IPC
     └── RemoteFileService (AIDL IPC)
```

#### 远程文件系统 IPC 架构

Root/Shizuku 模式下的文件操作通过 AIDL IPC 实现：

```
客户端 (App 进程)                    服务端 (Root/Shizuku 进程)
IRemoteFileSystemProvider  ──────>  RemoteFileSystemProvider
IRemoteInputStream        ──────>  RemoteInputStream
IRemoteSeekableByteChannel ─────>  RemoteSeekableByteChannel
IRemotePosixFileStore     ──────>  RemotePosixFileStore
IRemotePathObservable     ──────>  RemotePathObservable (inotify)
```

### 2.3 工具模块设计

工具系统采用分组+卡片导航模式：

```
ToolHostActivity
└── ToolGroupFragment (由 ToolGroupPage 枚举控制)
    ├── FILE_TOOLS      文件搜索 / 重复查找 / 空文件夹 / 文件比较 / 加密
    ├── STORAGE_TOOLS   存储分析 / 回收站 / 最近文件
    └── SYSTEM_TOOLS    应用管理 / 终端
```

每个工具项 (`ToolItem`) 包含：图标资源、标题资源、描述资源、启动 Intent。

### 2.4 媒体工具设计

`MediaToolsFragment` 提供卡片式功能入口：

| 功能 | 描述 | 实现方式 |
|------|------|----------|
| 视频合并 | 多不同格式视频合并为一 | normalizeVideo + concat demuxer |
| 音频提取 | 从视频中提取音轨 | extractAudio (stream copy) |
| 视频剪切 | 按时间范围裁剪 | trim (stream copy) |
| 视频压缩 | 降低比特率重编码 | videoCompress |
| 视频截帧 | 提取指定时间点帧 | videoSnapshot |
| GIF 制作 | 视频片段转 GIF | gifMake |
| 格式转换 | 音视频格式互转 | convert |

#### 视频合并流程设计

```
选择文件 → MediaInfo 采集 → determineMergeTarget (分辨率/码率)
    → doSmartMerge
        → 对每个文件: isFileCompatibleWithTarget?
            ├── 兼容: 直接使用
            └── 不兼容: tryNormalizeFile (多策略降级)
                ├── Strategy 1: 目标参数
                ├── Strategy 2: 原始分辨率
                ├── Strategy 3: 降低码率
                └── Strategy 4: 半分辨率
        → mergeFiles (concat demuxer)
```

#### normalizeVideo 关键设计

- **宽高比保持**：缩放时保持源视频宽高比，多余区域黑边填充（Letterbox/Pillarbox）
- **HW 帧安全处理**：HW 解码器输出帧需 `av_hwframe_transfer_data()` 转为 CPU 帧
- **延迟 sws 创建**：根据实际解码帧格式（而非解码器上下文格式）创建颜色空间转换器
- **编码器降级**：HW encoder → SW encoder 自动回退

### 2.5 操作日志 UI 设计

`OperationLogBottomSheet`（实际为居中 Dialog）为耗时操作提供实时反馈：

```
┌──────────────────────────────┐
│  🔧 标题           00:12     │  ← 状态图标 + 标题 + 计时
│  ═══════════════════════════ │  ← 进度指示器
│  格式统一           2/5      │  ← 步骤描述 + 进度数字
│  ┌────────────────────────┐  │
│  │ ⏭ video1.mp4 — 跳过    │  │
│  │ ⏳ video2.mp4           │  │  ← 等宽字体日志区
│  │ ✅ video2.mp4 (3.2s)   │  │
│  │ ⏳ video3.mp4           │  │
│  └────────────────────────┘  │
│                     [取消]   │  ← 操作按钮
└──────────────────────────────┘
```

特性：
- Material 3 风格，28dp 圆角
- 居中显示（85% 宽 × 65% 高）
- 进度指示器：不确定→确定模式切换
- 最大日志 50,000 字符，自动裁剪
- 完成后状态图标变色（成功=primary，失败=error）

### 2.6 文件加密设计

`EncryptionFragment` 提供 AES 对称加密：

- 支持单文件和批量加密/解密
- 密码输入 + 确认
- 加密文件扩展名 `.enc`
- 集成 `OperationLogBottomSheet` 显示进度

### 2.7 内置查看器设计

| 查看器 | 技术方案 |
|--------|----------|
| 图片 | Coil + SubsamplingScaleImageView（大图分块加载）+ PhotoView |
| 视频 | ExoPlayer (Media3) + 手势控制（±15s 快进快退）+ 倍速 |
| 音频 | ExoPlayer + 专辑封面 |
| PDF | PdfRenderer（逐页位图渲染）|
| CSV | WebView HTML 表格渲染 |
| 文本 | 自定义编辑器 + ICU4J 编码检测 |
| 十六进制 | RecyclerView 分页加载 |
| 电子书 | WebView 渲染 |

#### 查看器全屏统一设计

沉浸式查看器（图片/视频/音频/PDF/电子书/CSV）采用统一的叠加式工具栏模式：

- **布局**: FrameLayout 根布局 → 内容视图 → 叠加 FrameLayout(appBarLayout + MaterialToolbar)
- **主题**: `Theme.MaterialFiles.Material3.Immersive` — 透明状态栏，内容绘制到状态栏下
- **窗口 Insets**: `WindowCompat.setDecorFitsSystemWindows(false)` + appBarLayout 适配顶部 insets
- **点击切换**: `GestureDetector.onSingleTapConfirmed` 触发 `toggleUi()` — 工具栏动画淡出/滑出 + `WindowInsetsControllerCompat` 隐藏/显示系统栏
- **CSV 特殊处理**: HTML body padding-top 等于工具栏高度，初始内容不遮挡；滚动后内容自然穿到工具栏下方

交互式查看器（文本编辑器/十六进制/大文本）保留 CoordinatorLayout + AppBarLayout 常规模式。

#### CSV 查看器设计

- WebView 渲染 HTML `<table>`，支持暗色/亮色主题（CSS `prefers-color-scheme`）
- 粘性表头（`position: sticky`）
- 行号列
- 支持引号内逗号、转义引号的标准 CSV 解析
- 性能限制：最多渲染 10,000 行
- HTML 特殊字符转义（防 XSS）

### 2.8 FFmpeg 媒体操作设计

#### 视频压缩参数对话框

```
┌──────────────────────────────┐
│  视频压缩选项                 │
│                              │
│  比特率                       │
│  ○ 低 (500 kbps)            │
│  ● 中 (1500 kbps)           │
│  ○ 高 (3000 kbps)           │
│                              │
│  分辨率                       │
│  ● 保持原始                   │
│  ○ 720p                     │
│  ○ 480p                     │
│  ○ 360p                     │
│                              │
│  帧率                         │
│  ● 保持原始                   │
│  ○ 30 fps                   │
│  ○ 24 fps                   │
│  ○ 15 fps                   │
│                              │
│         [取消]  [确定]        │
└──────────────────────────────┘
```

#### 视频增强强度对话框

单选列表：轻度(0.5) / 中度(1.5) / 强度(3.0) — 控制锐化/去噪强度

#### FFmpeg 编码器策略

- **编码器回退链**: h264_mediacodec → mpeg4（因未编译 libx264）
- **时基设置**: 编码器 time_base = `av_inv_q(fr)`（帧率倒数），避免 mpeg4 VOP 增量限制
- **pts 重缩放**: 所有编码函数使用 `av_rescale_q` 从输入流时基转换到编码器时基
- **GIF 时间戳**: 编码器 1/fps → muxer 1/100 厘秒转换
- **GIF 帧独立**: `av_frame_make_writable(scaled)` 确保编码器差分优化不共享缓冲区
- **INVALIDDATA 容错**: 解码循环跳过 HW 解码器返回的损坏帧

## 3. 数据流设计

### 3.1 文件列表数据流

```
FileListFragment
    │ observe
    ▼
FileListViewModel
    │ load / navigate
    ▼
FileSystemProviders
    │ createNewDirectoryStream
    ▼
LinuxFileSystemProvider / ArchiveFileSystemProvider / ...
    │ syscall / libarchive / ContentResolver
    ▼
OS Kernel / Archive File / SAF
```

### 3.2 文件操作数据流

```
用户操作 (复制/移动/删除)
    │
    ▼
FileJobService (前台服务)
    │ 创建
    ▼
FileJob (后台线程)
    │ 执行
    ▼
FileSystemProvider (NIO2 API)
    │ 通知
    ▼
Notification (进度条 + 冲突对话框)
```

## 4. 安全设计

| 方面 | 措施 |
|------|------|
| 网络隔离 | `<uses-permission android:name="android.permission.INTERNET" tools:node="remove"/>` |
| 文件权限 | 运行时权限申请 + SAF 授权 |
| Root 安全 | Root 操作通过 AIDL IPC 隔离进程 |
| 加密安全 | AES 加密，密码不持久化 |
| 代码混淆 | Release 启用 ProGuard/R8 |

## 5. 性能设计

| 方面 | 策略 |
|------|------|
| 文件列表 | RecyclerView + DiffUtil + ViewHolder 复用 |
| 图片加载 | Coil 异步加载 + 内存缓存 + 磁盘缓存 |
| 大文件 | SubsamplingScaleImageView 分块渲染 |
| 原生操作 | JNI 直接系统调用，避免 Java IO 开销 |
| FFmpeg | HW 优先编解码 + 静态精简构建 |
| LTO 优化 | Native 库启用 Link-Time Optimization |
| 视频处理 | MediaCodec 硬件编码（HW→SW 降级）|
